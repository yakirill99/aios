# Матрица влияния между скважинами

`response_matrix.csv` — карта того, кто на кого влияет в пласте, насколько
сильно и с какой задержкой. Получена из управляемого эксперимента на
гидродинамической модели, не из истории.

---

## Зачем она нужна

Скважины стоят в одном пласте и связаны через общее поле давления.
Изменили режим одной — через несколько месяцев отозвалась соседняя.
В исходных данных этих связей нет: геометрия есть в деке, но подавать её
агенту запрещено регламентом — он должен понимать объект по поведению,
ровно как по промысловой телеметрии на реальном месторождении.

Без матрицы система действует вслепую: меняет режим, не зная, кого это
заденет. С матрицей появляются три вещи, без которых архитектура не
работает.

**Кластеризация фонда.** Сильно связанные скважины образуют группу.
Внутри группы решения надо согласовывать, между группами — можно принимать
независимо. На этом держится Candidate Packer: если кластеры почти не
влияют друг на друга, их кандидатов можно упаковать в один прогон
симулятора вместо N, и это даёт выигрыш в разы.

**Учёт задержки.** Медиана лага 4 месяца (квартили 2–10). Дёргать
скважину каждый месяц бессмысленно: результат предыдущего действия ещё не
проявился, а за переключения уже заплачено. Матрица задаёт минимальный
разумный интервал между воздействиями.

**Обоснование решений.** «Наращиваем закачку в 42-ю, потому что она
подпирает 56-ю с эффектом +12,5 м³/сут» — это то объяснение, которое
ждёт жюри по критерию интерпретируемости, и оно опирается на измерение,
а не на догадку.

---

## Откуда она взялась

Из состояния на 01.01.2014 меняли режим **одной** скважины ступенькой
(±30% от текущего), остальные не трогали, прогоняли 36 месяцев вперёд и
сравнивали ряды каждой скважины с опорным вариантом.

49 скважин × 2 уровня + опорный = **99 прогонов**, 47 минут на шести
процессах.

**Почему эксперимент, а не история.** История 2007–2013 даёт 80 месяцев
наблюдений на 2 401 возможную пару — задача недоопределена на порядок.
Плюс это одна траектория управления с бедным возбуждением: что в ней не
шевелили, из неё не идентифицируется в принципе. А корреляция в истории
часто ложная — две скважины отзываются синхронно не друг на друга, а на
третью.

Возмущающий прогон даёт **причинность**: меняли ровно одно, остальное
зафиксировано.

## Что внутри

615 связей выше порога, из них 343 по нефти и 272 по жидкости.
Цикл при загрузке печатает: «42 источников, медиана лага 4 мес, связей
для агента 106» — последнее число это связи, отфильтрованные по
оставшемуся горизонту.

| Колонка | Смысл |
|---|---|
| `source` | скважина, режим которой меняли |
| `source_kind` | `prod` — добывающая, `inj` — нагнетательная |
| `level` | множитель режима: 0.7 (ослабили) или 1.3 (усилили) |
| `observed` | скважина, которая отозвалась |
| `metric` | `oil` — отклик по нефти, `liq` — по жидкости |
| `peak_abs` | сила отклика, м³/сут — **главная величина** |
| `peak_rel` | то же в долях от уровня наблюдаемой скважины |
| `base_level` | средний уровень наблюдаемой в опорном варианте |
| `lag_month` | месяцев до достижения половины пика |
| `peak_month` | месяц самого пика |
| `sign` | знак отклика |

Пример строки:

```
42, inj, 1.3, 56, oil, 12.52, 1.15, 10.9, 15, 22, +
```

Читается так: нарастили закачку в скважине 42 на 30% — добыча нефти в
скважине 56 выросла на 12,5 м³/сут (это +115% от её уровня 10,9),
половина эффекта достигнута через 15 месяцев, пик на 22-м.

## Два предупреждения при интерпретации

### Знак сам по себе ничего не значит

Все добывающие управляются по `LRAT` — целевому дебиту **жидкости**.
Симулятор держит его, пока хватает пластового давления. Значит рост
закачки **не увеличивает отбор жидкости** — он зафиксирован. Меняется
только обводнённость: приходит больше воды, доля нефти в той же жидкости
падает. Одновременно поддерживается давление, что работает в плюс.

Что перевесит — зависит от геометрии, и знак принципиально может быть
любым. Поэтому доля положительных откликов у нагнетательных ровно 50%,
и это нормально, а не признак ошибки.

### Проверять надо антисимметрию

Настоящий критерий физичности: если усиление даёт плюс, то ослабление той
же пары должно давать минус.

```
42 (inj, x1.3) -> 56: +12.52 м³/сут
42 (inj, x0.7) -> 56:  -4.31 м³/сут     зеркально
42 (inj, x1.3) ->  9:  +4.63
42 (inj, x0.7) ->  9:  -4.25            зеркально
```

**Из 153 пар с откликом на оба уровня антисимметричны 149 (97%).**
Связи реальные, не шум.

## Что с ней делать дальше

Это сырые данные управляемого эксперимента, а не готовый граф. Поверх
строятся три слоя:

1. **Корреляционный фильтр по истории** — отсекает пары, у которых в
   реальной динамике 2007–2013 нет согласованного поведения. Убирает
   численные артефакты.
2. **CRM-модель** — даёт физически осмысленные веса и постоянные времени
   для пар «закачка → добыча». Балансовое ограничение отсекает ложные
   корреляции.
3. **Верификация возмущениями** — эта матрица. Подтверждает или
   опровергает то, что дали первые два слоя.

У каждой связи в итоговом графе должна быть **уверенность**: связь,
подтверждённая прогоном, и связь из корреляции — разного качества, и
координатор обязан их различать.

Рёбра «добыча → добыча» и «закачка → закачка» выводятся из общих
источников: если две скважины отзываются на одно и то же возмущение
похожим образом, они дренируют общую зону.

## Как воспроизвести

```bash
cd ~/aios/scripts

python3 probe_wells.py make --cut 2014-01-01 --months 36
./run_probes.sh                    # ~47 мин на 6 процессах
./analyze_probes.sh                # пороги 2% и 0.3 м³/сут
./analyze_probes.sh 0.01 0.1       # чувствительнее, больше шума
```

Результат: `~/aios-data/probes/response_matrix.csv`

Осторожно: `probe_wells.py make` пересоздаёт деки. Уже посчитанные
варианты он пропускает, но с флагом `--force` затрёт всё, включая
результаты многочасовых прогонов.

## Известные ограничения

**Одна рабочая точка.** Матрица снята из состояния на 01.01.2014 при
базовых режимах. По мере выработки залежи связи меняются: обводняется
зона, меняется поле давления. Для скользящего горизонта её стоит
пересчитывать раз в несколько лет модельного времени.

**Линейность не проверена.** Мы меняли режим на ±30%. Отклик на ±50%
может быть непропорциональным — гидродинамика нелинейна. Если оптимизатор
будет предлагать сильные воздействия, эффект надо проверять прогоном, а
не экстраполяцией по матрице.

**Одиночные возмущения.** Влияние двух одновременных изменений не
обязано быть суммой отдельных. Матрица показывает структуру связей, а не
даёт формулу для предсказания — окончательное решение всё равно
подтверждается полным прогоном.

**Горизонт 36 месяцев.** Связи с лагом больше трёх лет в матрицу не
попали. Судя по распределению (максимум 30 месяцев, 75-й перцентиль 10),
таких немного, но они возможны.
