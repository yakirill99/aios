# Установка с нуля. Для организаторов и команды

Пошагово, на чистой машине, без предположений о том, что уже стоит.
Каждый шаг заканчивается проверкой: если она не прошла, дальше идти
нельзя.

Проверено 11.09.2026 на Ubuntu 24.04 в WSL2. Время: около получаса,
из них двадцать минут — скачивание архива и сборка образа симулятора.
Дашборд поднимается за минуту и от остального не зависит: если нужен
только интерфейс, достаточно разделов 1, 2 и 5.

Короткая версия для жюри — `submission/RUN.md`. Здесь полный путь со
всеми граблями, на которые мы наступили сами.

---

## 0. Что понадобится

| Что | Зачем | Обязательно |
|---|---|---|
| Docker с плагином Compose | симулятор и дашборд | да |
| git | склонировать репозиторий | да |
| python3 (3.10+) | расчёт ЧДД, сборщик и воркер дашборда | да |
| curl, wget, tar, zstd | скачать и распаковать архив | да |
| 8 ГБ свободного места | архив, дека, результаты прогонов | да |
| 6+ потоков CPU | параллельные прогоны кандидатов | для раздела 6 |

Проверка:

```bash
docker --version && docker compose version
git --version && python3 --version
tar --zstd --help >/dev/null && echo "zstd есть"
df -h ~ | tail -1
```

Если `docker compose version` ругается, установлен старый
`docker-compose` — поставьте плагин:
`sudo apt install docker-compose-plugin`.

Если `docker ps` требует sudo, добавьте себя в группу и перелогиньтесь:
`sudo usermod -aG docker $USER`.

Дополнительных пакетов Python на хосте не нужно: сборщик дашборда и
воркер очереди написаны на стандартной библиотеке. `fastapi`, `uvicorn`
и `PyYAML` ставятся внутрь образа при сборке и на хост не попадают.
Исключение — `pydantic` для агентного слоя, см. раздел 5b.

Интернет нужен только на сборку образов: Docker Hub и 19 пакетов с
PyPI, все готовыми колёсами, компилятор не требуется. После сборки
дашборд работает автономно — Chart.js лежит в репозитории, внешних
ссылок в интерфейсе нет.

## 3. Архив данных

**Делайте это ДО первого запуска дашборда.** Docker при старте создаёт
каталог `~/aios-data` под точку монтирования с владельцем root, и
распаковка в него потом упирается в права.

Публичная ссылка Яндекс.Диска ведёт на страницу просмотра: `wget` по
ней скачает 53 КБ вёрстки вместо архива. Прямая ссылка берётся через
API:

```bash
cd ~
PUB="https://disk.yandex.ru/d/fDUvbF-NcpWExA"
HREF=$(curl -s "https://cloud-api.yandex.net/v1/disk/public/resources/download?public_key=$PUB" \
       | python3 -c "import sys,json;print(json.load(sys.stdin)['href'])")
wget -O aios-submit-data.tar.zst "$HREF"
```

Проверка до распаковки — размер около 126 МБ и правильный формат:

```bash
ls -lh aios-submit-data.tar.zst
file aios-submit-data.tar.zst           # Zstandard compressed data
```

Если размер в десятки килобайт — скачалась страница, повторите с
`HREF`. Можно и просто сохранить файл через браузер.

Распаковка и раскладка:

```bash
tar --zstd -xf aios-submit-data.tar.zst -C ~
sha256sum -c ~/SHA256SUMS | grep -v ': OK$' || echo "суммы сошлись"

mv ~/data  ~/aios-data
mv ~/model ~/aios/model
```

Проверка:

```bash
ls $DATA_ROOT                           # full34, abl_*, kam_*, probes, runs, llm_cache
ls $AIOS_ROOT/model/Model_Y_opm | head
python3 -c "
import json; d=json.load(open('$DATA_ROOT/full34/result.json'))
print('ЧДД', d['npv'], '| планка', d['baseline'], '| допущения', d['assumptions'])"
```

Ожидается 1165.899…, планка 1018.9855…, допущения пустые.

## 5. Дашборд

```bash
cd $AIOS_ROOT
cp .env.example .env
./scripts/dashboard_preflight.sh --fix
docker compose up --build -d
```

`dashboard_preflight.sh` проверяет каталоги под томами и их владельца.
Это не формальность: если `~/aios-data/queue` не существует, Docker
создаст его от root, а контейнер работает под обычным пользователем и
писать туда не сможет. Обычный `mkdir -p` уже созданный каталог не
чинит — нужна смена владельца, её скрипт и делает.

Первая сборка на чистой машине — около минуты (скачивание базового
образа и установка зависимостей), дальше секунды.

Куда заходить:

| Адрес | Что там |
|---|---|
| <http://localhost:8000> | **главный экран**: ЧДД против планки, фонд, агенты |
| <http://localhost:8000/dashboard.html> | **журнал прогона**: шаг за шагом, кандидаты, выигрыш |
| <http://localhost:8000/docs> | документация API, можно дёргать ручки из браузера |

В шапке слева — переходы между двумя экранами, работают в обе стороны.
Справа — индикатор источника данных и, если прогон идёт, полоса
прогресса с номером шага.

На главном экране переключатель **«простой / продвинутый»**. В простом
часть карточек скрыта; продвинутый раскрывает гидродинамическую модель,
управляющие воздействия, содержимое `wells_schedule.inc`, параметры
оптимизации и лог. Если экран кажется полупустым — вы в простом режиме.

Проверка:

```bash
curl -s localhost:8000/health
curl -sD- localhost:8000/api/state -o /dev/null | grep -i x-data-source
```

В `health` смотрите `queue_writable` — должно быть `true`. Пока сводка
не собрана, источник данных `demo`, это штатно.

Показать наш прогон вместо эталона:

```bash
cd $AIOS_ROOT
PYTHONPATH=src python3 -m aios.dashboard.collect
curl -sD- localhost:8000/api/state -o /dev/null | grep -i x-data-source   # live
```

Порт занят? Поменяйте `PORT` в `.env` и повторите `docker compose up -d`.

### 5а. Запуск прогонов из интерфейса

Кнопка «Запустить прогон» в шапке открывает меню: месторождение из
`configs/decks.yaml`, пресет, параметры и режим LLM. Параметры
проверяются на сервере по схеме из `configs/run_presets.yaml`.

**Дашборд сам симулятор не запускает.** Он кладёт задание в очередь
`~/aios-data/queue`, а забирает его отдельный процесс — воркер. В образе
дашборда нет OPM Flow, и каталог с результатами смонтирован только на
чтение: испортить данные расчёта интерфейс не может.

Воркер запускается там, где стоит симулятор. Отдельный терминал,
держать открытым:

```bash
cd $AIOS_ROOT
./scripts/dashboard_worker.sh
```

Посмотреть, какую команду он соберёт, ничего не запуская:

```bash
./scripts/dashboard_worker.sh --dry-run
```

Пока воркер не запущен, задание лежит в статусе «В очереди». Интерфейс
об этом говорит прямо: в шапке появляется «Воркер не запущен», а в окне
запуска — команда для старта. Проверить отдельно:

```bash
curl -s localhost:8000/health | grep -o '"worker_alive":[^,]*'
```

Пресет «Проигрывание записи» симулятор не запускает и отрабатывает
мгновенно — им удобно проверять, что связка жива.

### 5б. Сборка для показа

Если дашборд отдаётся жюри или заказчику, поставьте в `.env`:

```
AIOS_READONLY=1
```

Кнопка запуска исчезает, ручки запуска отвечают 403. Смысл простой:
случайно запущенный на защите полный горизонт считается часами, а
задание без воркера просто зависнет в очереди.

## 5b. Языковая модель: Ollama и qwen3

Этот раздел нужен **только для агентного слоя**. Расчёт ЧДД, проверка
расписания, валидатор физики и дашборд работают без него: режим `off`
принимает решения правилами и даёт полный результат сам по себе.

### Что каким режимом требуется

| Режим | Ollama | Модель скачана | Кэш | Что получится |
|---|---|---|---|---|
| `off` | не нужна | не нужна | не нужен | 1 160,700 при лимите 8 |
| `replay` | не нужна | **не нужна** | обязателен | 1 152,837 |
| `live` | нужна | нужна | пополняется | зависит от модели |

Режим `replay` берёт ответы из `cache/llm` в репозитории и к Ollama не
обращается. Скачивать девять гигабайт ради проверки воспроизводимости
не требуется — достаточно правильно назвать модель, потому что её имя
входит в ключ кэша.

### Минимум для `replay`

```bash
pip install --break-system-packages pydantic
python3 -c "import agents; print('agents импортируется')"

export AIOS_LLM_MODEL=qwen3:14b
echo "export AIOS_LLM_MODEL=qwen3:14b" >> ~/.bashrc

cp -r $AIOS_ROOT/cache/llm $DATA_ROOT/llm_cache
ls $DATA_ROOT/llm_cache/*.json | wc -l          # 112
```

Флаг `--break-system-packages` обязателен на Ubuntu 24.04: без него pip
откажется ставить пакет в системный Python (PEP 668).

### Полная установка для `live`

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama serve &                      # если не поднялся как служба
ollama pull qwen3:14b               # около 9 ГБ
ollama list
curl -s localhost:11434/api/tags | head -c 300
```

Требования: около 10 ГБ на диске и столько же оперативной памяти;
на видеокарте работает заметно быстрее, но не обязателен. Один шаг
цикла с моделью занимает примерно на минуту дольше, чем на правилах.

Если Ollama слушает не на localhost, задайте адрес:

```bash
export OLLAMA_HOST=http://<адрес>:11434
```

Модель поменьше (`qwen3:4b`) тоже работает, но **с ней не
воспроизвести сданные числа**: кэш собран на `qwen3:14b`, и при другом
имени каждый запрос даст промах.

### Проверка после прогона

```bash
python3 -c "
import json; d=json.load(open('$DATA_ROOT/check_replay/result.json'))
print(d['npv'], d['llm_mode_effective'], 'моделью', d['llm_steps'],
      'правилами', d['rule_steps'])"
```

Ожидается `1152.837 replay моделью 8 правилами 0`, а в итоговой строке
прогона — «вызовов: 0, из кэша: 24, откатов на правила: 0».

### Три сбоя, которые выглядят одинаково

Все три дают 1 160,700 вместо 1 152,837, и во всех трёх цикл честно
пишет причину в лог, но прогон не прерывает.

**`agents.py не найден — цикл идёт на правилах`.** Файл на месте, нет
`pydantic`. Формулировка вводит в заблуждение, смотрите на настоящую
причину: `python3 -c "import agents"`.

**`промах кэша в режиме replay — возврат к правилам`.** Задано другое
имя модели либо кэш не скопирован в `$DATA_ROOT/llm_cache`.

**`откатов на правила: N` при ненулевых вызовах в режиме `live`.**
Ollama не отвечает или модель не скачана.

## 6. Полное воспроизведение расчёта

Образ симулятора собирается один раз. По времени: от десяти минут до
получаса, почти всё уходит на `apt-get install` внутри образа. При
обрыве сети сборка падает с `context canceled` — повторный запуск
продолжает с кеша слоёв, а не с нуля, так что просто запустите команду
ещё раз.

```bash
cd $AIOS_ROOT
docker build -t aios/opm:2026.04 -f scripts/Dockerfile scripts/
docker images | grep aios/opm
```

Расписание с нуля:

```bash
cd $AIOS_ROOT/scripts
./run_schedule.sh --inc ../submission/wells_schedule.inc
```

Скрипт сам сверит результат с `npv_claimed.txt` и напечатает
«ТЕСТ НА КРУГ ПРОЙДЕН». Полтора-два минуты.

Физика:

```bash
./validate.sh $DATA_ROOT/runs/sched --since 2014-01-01
```

Ожидается «РЕЗУЛЬТАТ ФИЗИЧЕСКИ КОРРЕКТЕН» дважды — по всему горизонту и
по управляющему окну.

Агент без сети:

```bash
cp -r $AIOS_ROOT/cache/llm $DATA_ROOT/llm_cache
python3 rolling_horizon.py run --llm replay --candidates 8 \
    --workdir $DATA_ROOT/check_replay
```

Ожидается 1 152,837 млн при нуле сетевых вызовов.

Оптимизация целиком, как получено сданное расписание (около двух
часов):

```bash
python3 rolling_horizon.py run --llm off --candidates 34 \
    --workdir $DATA_ROOT/check_full34
```

Каждому прогону — свой `--workdir`: два прогона в один каталог
затирают журнал друг друга.

## 7. Если что-то пошло не так

**`cannot move ... Permission denied` при распаковке данных.** Каталог
`~/aios-data` создан Docker под root. Остановите контейнер, удалите
каталог, распакуйте заново, поднимите контейнер:

```bash
docker compose -f $AIOS_ROOT/docker-compose.yml down
sudo rm -rf $DATA_ROOT && mv ~/data $DATA_ROOT
cd $AIOS_ROOT && docker compose up -d
```

**Архив не распаковывается, `unsupported format`.** Скачана
HTML-страница вместо файла. Смотрите раздел 3, вариант с `HREF`.

**`Could not import module "aios.dashboard.server"`.** Образ собран
из кеша со слоем-заглушкой. Пересоберите без кеша:
`docker compose build --no-cache && docker compose up -d`.

**Дашборд показывает `demo`, хотя данные распакованы.** Не собрана
сводка: `PYTHONPATH=src python3 -m aios.dashboard.collect`. Именно
`state.json` цикл сам не пишет.

**В сводке «связей 0».** Исправлено: `collect.py` читает
`response_matrix.csv` как `utf-8-sig`, BOM больше не мешает распознать
колонку `source`. Если строки всё же отбрасываются, посмотрите
сообщение — в нём видно, какого столбца не хватает.

**Задание висит «В очереди» и ничего не происходит.** Не запущен
воркер — дашборд задания только ставит. Запустите
`./scripts/dashboard_worker.sh` в отдельном терминале и не закрывайте
его. Проверка:
`curl -s localhost:8000/health | grep -o '"worker_alive":[^,]*'`.

**`queue_writable: false` в ответе `/health`.** Каталог
`~/aios-data/queue` принадлежит root: его создал Docker, когда каталога
не было на хосте. Лечится `./scripts/dashboard_preflight.sh --fix` и
перезапуском контейнера. `mkdir -p` здесь не помогает — каталог уже
существует, и команда молча ничего не делает.

**Нажатие «Поставить в очередь» показывает ошибку прав.** То же самое,
что выше: сервер отвечает 503 и пишет настоящую причину прямо в окне.

**`run_flow` или `run_py` не найдены.** Это функции из
`scripts/lib_common.sh`, их надо подтянуть в текущую оболочку:
`source ./lib_common.sh`. Порядок аргументов: `run_py <скрипт>
<каталог для /out> [аргументы]`.

**Расчёт даёт 922,7 вместо 1 018,986.** Включён `chargeInitialPump` на
управляющем окне. Планка должна считаться без него: флаг нужен только
на полной истории 2007–2015.

**Режим `replay` даёт 1 160,7 вместо 1 152,837.** Либо не установлен
`pydantic`, либо задано не то имя модели — см. раздел 5b. Оба случая
цикл печатает в лог, но прогон не прерывает.

**Прогон падает по месту на диске.** Каталоги кандидатов занимают
десятки гигабайт. Чистка: `scripts/cleanup.sh`. Каталоги
`runs/history_full` и `runs/baseline` из чистки исключены намеренно —
это опорные прогоны.

├── submission/          что сдаём: расписание, число, RUN.md

│   └── dashboard_worker.sh      воркер очереди прогонов

├── docs/                архитектура, проверки, эта инструкция
