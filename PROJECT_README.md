# AIOS · Трек 1 — мультиагентная система управления фондом скважин

Система подбирает расписание управляющих воздействий на 49 скважинах,
максимизируя ЧДД на заданном горизонте при соблюдении технологических
ограничений.

**Горизонт Model_Y:** 01.01.2014 → 01.12.2015, 23 управляющих месяца.
**Ранжирование:** по абсолютному подтверждённому ЧДД, не по приросту.

---

## Быстрый старт

```bash
cd ~/aios/scripts

./setup_dirs.sh          # структура каталогов, проверка окружения
./smoke_test.sh          # проверка контура на эталонной SPE1
./verify_reference.sh    # сверка расчёта ЧДД с эталоном организаторов
./prepare_baseline.sh 2014-01-01 2015     # планка
python3 rolling_horizon.py run --step 3   # цикл оптимизации
```

Требуется Docker с образом `aios/opm:2026.04` — сборка в `INSTALL.md`.

## Скрипты: что и зачем

Все пути заданы в `lib_common.sh` — единственном месте. Переопределяются
переменными окружения: `MODEL_DIR=/путь ./benchmark.sh`.

### Основа

| Файл | Назначение |
|---|---|
| `lib_common.sh` | пути, стражи диска и памяти, запуск симулятора |
| `setup_dirs.sh` | создание структуры, проверка прав и окружения |
| `smoke_test.sh` | проверка контура на SPE1 |
| `benchmark.sh` | замер: время прогона, оптимум параллельности, место |

### Расчёт денег

| Файл | Назначение |
|---|---|
| `npv_official.py` | ★ обёртка над эталоном организаторов. Своей арифметики нет |
| `summary_to_csv.py` | мост UNSMRY → 14 колонок для расчёта ЧДД |
| `verify_reference.sh` | сверка с эталоном 5 326,5 млн |

**Ключевое:** расчёт ЧДД идёт только эталонным кодом организаторов.
Вторая реализация формулы означала бы расхождение при контрольном
пересчёте, а попытка одна.

### Подготовка сценариев

| Файл | Назначение |
|---|---|
| `prepare_history.sh` | прогон истории → снимок пласта + датасет |
| `prepare_baseline.sh` | режимы заморожены → планка ЧДД |
| `schedule_builder.py` | ★ генератор `wells_schedule.inc` |
| `run_schedule.sh` | прогон расписания + сравнение с планкой |

### Матрица влияния

| Файл | Назначение |
|---|---|
| `probe_wells.py` | генерация возмущений и разбор откликов |
| `run_probes.sh` | прогон 99 вариантов |
| `analyze_probes.sh` | сборка матрицы |

Возмущающие прогоны: меняем режим одной скважины на ±30%, смотрим отклик
остальных. Это управляемый эксперимент — даёт причинность, а не
корреляцию.

### Оптимизация

| Файл | Назначение |
|---|---|
| `rolling_horizon.py` | ★ цикл скользящего горизонта с триггерами |
| `read_state.py` | чтение состояния фонда (внутри контейнера) |
| `candidates.py` | генератор кандидатов, дискретная сетка |
| `run_candidates.sh` | пакетный прогон кандидатов |

### Проверка и обслуживание

| Файл | Назначение |
|---|---|
| `validate_output.py` | ★ физическая корректность на всём горизонте |
| `validate.sh` | обёртка запуска валидатора |
| `cleanup.sh` | уборка результатов |
| `cleanup_stale.sh` | удаление данных от устаревшей даты отсечки |
| `git_prepare.sh` | подготовка репозитория к коммиту |

### Агентный слой

| Файл | Назначение |
|---|---|
| `llm_client.py` | клиент LLM: режимы off / live / replay |

Режим `off` обязан работать всегда: система деградирует до правил, и это
доказывает, что числа не приходят из генерации текста.

## Что важно знать

**Расчёт ЧДД проверен.** Сверка с эталоном организаторов на периоде
2007–2015: расхождение доведено с 2,54% до ~1,5% через параметр
`chargeInitialPump`. Подтверждено счётчиком событий: смены ЭЦН 57 против
58, остановки 48 против 48, переводы 15 против 15.

**Единицы.** OPM Flow не поддерживает `WOMT` — это ключевое слово
tNavigator. Масса нефти считается из объёма: `WOPT × 0,833` т/м³
(`DENSITY` в деке даёт 832 и 834 кг/м³).

**Дека правилась.** Из исходной убраны конструкции tNavigator: блок
`#if 0`, `IMPLICIT`, лишний терминатор после `WELLDIMS`. Каждая правка в
`model/CHANGES_FOR_OPM.md`.

**Короткий горизонт меняет стратегию.** 23 месяца при медиане лага
отклика 6 месяцев по нефти: форсирование отбора работает сразу, закачка
успевает проявиться только в первой половине окна. Матрица фильтруется
динамически: связь полезна, если лаг + месяц вмешательства ≤ 23.

**Место на диске.** Прогон без снимков — 25 МБ, со снимками до 1,3 ГБ.
Все скрипты отключают `RPTRST` для пробных прогонов. Внутри WSL `df`
показывает размер виртуального диска, поэтому свободное место считается
как минимум из ext4 и диска C.

## Сдача

В `submission/`:
- `wells_schedule.inc` — расписание, читается моделью без правок
- `npv_claimed.txt` — заявленное абсолютное значение ЧДД
- исходный код, документация, `docker compose up`

Один контрольный расчёт на стороне организаторов. Расхождение сверх пары
процентов — дисквалификация, повторов нет.
